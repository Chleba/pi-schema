# pi-config

This directory is the user's pi agent configuration, versioned in the
pi-chleba fork so it travels with the code. The live agent config at
`~/.pi/agent` is a set of symlinks into this directory (and into the repo's
extension directories); [`./install.sh`](./install.sh) creates and maintains
those links.

## What is versioned here

| Versioned file | Linked as (under `~/.pi/agent/`) |
| -------------- | -------------------------------- |
| `settings.json` | `settings.json` |
| `model-params.json` | `model-params.json` |
| `orch/config.json` | `orch/config.json` |
| `themes/omarchy-system.json` | `themes/omarchy-system.json` |
| `skills/` (whole dir) | `skills` |
| `extensions-disabled/` (whole dir) | `extensions-disabled` |

`skills/` holds 16 skill dirs plus the 3 top-level files (`AGENT_WORKFLOW.md`,
`PROJECT_BOOTSTRAP.md`, `README.md`). Two of the skill dirs (`diagnose-crash`,
`omarchy`) are symlinks into `/usr/share/omarchy/...` — distro-provided skills,
kept as symlinks rather than duplicated. They point into
`/usr/share/omarchy/default/agents/skills/`, so both entries require Omarchy
installed at that path; on non-Omarchy machines those two entries are simply
absent.

`extensions-disabled/` holds parked extensions: `vllm.ts` lives only here;
`lmstudio.ts` is a plain copy of `../pi-chleba-extensions/lmstudio.ts`.

### Where the active extensions live

Active extensions are versioned elsewhere in the repo and symlinked into
`~/.pi/agent/extensions/` by `install.sh`:

| Extension | Repo location |
| --------- | ------------- |
| `ollamamq.ts`, `model-params.ts`, `omarchy-system-theme.ts`, `searxng.ts` | `../pi-chleba-extensions/` |
| `sampling-params.ts` | `../packages/coding-agent/examples/extensions/sampling-params.ts` |

## NOT versioned (on purpose)

- `auth.json` — credentials/secrets. Never commit, copy, or print it.
- `trust.json` — machine-specific trusted paths.
- `models.json`, `models-store.json` — generated by pi.
- `sessions/`, `npm/`, `pi-hermes-memory/`, `.pi-hermes-locks.sqlite*` —
  runtime state, caches, and lock files.

## New-machine bootstrap

```bash
git clone git@github.com:Chleba/pi.git
cd pi
./pi-config/install.sh
```

Then restore `~/.pi/agent/auth.json` manually — copy it from an existing
machine, or run `pi` and complete the auth login. `install.sh` never reads,
copies, or prints `auth.json`; it only warns when the file is missing.

`install.sh` is idempotent (safe to re-run any time). Files it overwrites are
backed up to `~/.pi/backups/<timestamp>/`, preserving paths relative to the
agent dir. Set `PI_CODING_AGENT_DIR` to target a different agent dir.

## Notes

- pi writes to `settings.json` itself — `lastChangelogVersion`, and the
  `packages` array on `pi install` / `pi remove`. Because the live file is a
  symlink, those writes land in this repo; commit them when they happen.
- Edits to files here apply live, immediately — everything under `~/.pi/agent`
  that is a symlink reads straight from the repo. No reinstall needed.
